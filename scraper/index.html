How deals flow, in 3D

Dots

What you seeWhat it means
A dot in a source's colourA deal from that partner, moving to the next step.
A dot that pauses in the queueA deal waiting for a person to review it.
A dot that turns grey and dropsA duplicate of a deal that is already on the site, so it is skipped.
A dot that turns red and dropsAn item with an impossible price, or one a reviewer rejected.
A purple dot on a dashed pathAn improvement being built (shown with In progress on).
Thin lines without dotsControl links: a trigger starting a run, or a run record being written.

With reduced motion turned on in your system settings, the model stays still: no dots and no slow rotation. Everything else still works.

3Today vs in progress

Everything on the Today layer is in the code now. The In progress layer adds work that is being built and reviewed but has not shipped.

Cuelinks Offers API v3 In progress

Reads offers page by page from the newer API, with a short pause between pages.

Failed runs recorded In progress

A partner outage is recorded as a failed run with a reason, not as a quiet run with no deals.

Real merchant link In progress

Duplicates are found by the store link inside an affiliate redirect, not by the redirect itself.

Invalid prices dropped In progress

Placeholder prices from feeds are rejected instead of being saved as “no price”.

Safer logging In progress

Run logs keep only what is needed to understand a run.

Scoring, niche filter, expiry Target

The longer-term pipeline: score items, set aside off-niche ones, and end deals when the offer ends. See Recommendations.
